# Location Model

> Данный документ является концепцией проекта Human Root of Trust.
>
> Документ не описывает реализацию и не является инструкцией по внедрению.

## 1. Назначение

Описать концепцию Location Model в рамках проекта Human Root of Trust.

## 2. Проблема

Артефакты системы существуют не изолированно, а размещаются в различных местах хранения.

Если расположение артефактов не описано явно, становится сложно:

- оценивать связанность системы;
- проектировать восстановление;
- анализировать последствия компрометации;
- контролировать распределение артефактов.

Для описания мест размещения артефактов используется Location Model.

## 3. Определение

Location — это логическая точка размещения артефактов, обладающая собственными характеристиками доступа, доверия и
доступности.

## 4. Что Location не является

Location не является:

- физическим адресом;
- устройством;
- identity;
- vault;
- recovery-процедурой;
- конкретным человеком.

## 5. Location Model

```text
LOC-01 Home
LOC-02 Safe
LOC-03 Trusted Relative
LOC-04 Bank
```

Это пример модели MVP 1.0.

Проект не требует фиксированного набора Location.

## 6. Свойства Location

```text
Access
Trust
Availability
```

## 7. Зависимости

- [vault-model](./vault-model.md)

## 8. Acceptance Criteria

- Location имеет уникальный код;
- Location имеет понятное назначение;
- характеристики Location документированы;
- артефакты могут быть связаны с Location;
- Location может использоваться в модели восстановления.

## 9. Non-goals

- реальные адреса;
- реальные места хранения;
- физическая безопасность;
- recovery implementation;
- backup implementation;
- OPSEC implementation.
