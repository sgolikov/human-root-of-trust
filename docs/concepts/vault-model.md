# Vault Model

> Данный документ является концепцией проекта Human Root of Trust.
>
> Документ не описывает реализацию и не является инструкцией по внедрению.

## 1. Назначение

Описать концепцию Vault Model в рамках проекта Human Root of Trust.

## 2. Проблема

Секреты, инструкции, recovery-материалы и карта системы часто хранятся совместно.

Это приводит к:

- избыточной связанности;
- усложнению восстановления;
- появлению единых точек отказа;
- повышению последствий компрометации.

Для разделения ответственности и снижения связанности используется Vault Model.

## 3. Определение

Vault — это логический контейнер артефактов, имеющий определённое назначение и правила доступа.

## 4. Что Vault не является

Vault не является:

- конкретным продуктом;
- конкретной базой данных;
- identity;
- устройством;
- аппаратным ключом;
- процедурой восстановления.

## 5. Vault Model

```text
Map DB
Recovery DB
Active DB
```

## 6. Типы Vault

```text
Active DB
    ежедневная работа

Recovery DB
    recovery-процессы

Map DB
    навигация по системе
```

## 8. Acceptance Criteria

- каждый Vault имеет понятное назначение;
- один Vault не должен совмещать все функции системы;
- компрометация одного Vault не должна автоматически давать полный контроль;
- назначение Vault документировано;
- связи между Vault документированы.

## 9. Non-goals

- выбор конкретного vault-продукта;
- реализация vault;
- шифрование;
- синхронизация;
- backup implementation;
- recovery implementation.
